# लोकमंगल न्यूज पोर्टल (Lokmangal News Portal)

महाराष्ट्रातील जनतेचा आवाज बुलंद करणारे आधुनिक, वेगवान आणि संपूर्ण रिस्पॉन्सिव्ह डिजिटल न्यूज पोर्टल.

---

## 📁 प्रोजेक्ट रचना (Project Structure)

प्रोजेक्ट दोन वेगळ्या भागांत विभागलेला आहे: **`frontend/`** (संपूर्ण वेबसाईट + Admin Panel — फक्त HTML / CSS / JS) आणि **`backend/`** (Python + MySQL). दोघे एकमेकांशी फक्त HTTP API (`/api/...`) वरून बोलतात.

```text
lokmangal news portal/
├── frontend/                       ← वेबसाईट (कोणताही सर्व्हर-कोड नाही)
│   ├── index.html
│   ├── css/                        style.css, responsive.css
│   ├── js/
│   │   ├── config.js               ← API चा पत्ता (API_BASE) इथे ठरतो
│   │   ├── i18n.js                 ← मराठी / English: शब्दकोश + भाषा बदलणारी बटणे
│   │   ├── content-en.js           ← आधीपासूनच्या १८ बातम्या + ६८ अंकांचा English मजकूर
│   │   └── app.js
│   ├── admin/                      ← Admin Panel (index.html, admin.js, admin-videos.js, admin.css)
│   └── assets/                     ← लोगो, फोटो (images/), साप्ताहिक PDF (pdf/) आणि Admin मधून अपलोड केलेले व्हिडिओ (videos/ — Git मध्ये जात नाही)
├── backend/                        ← Python (Flask) REST API + MySQL
│   ├── app.py                      ← सर्व्हर:  python app.py
│   ├── config.py                   ← .env मधील सेटिंग्ज वाचतो
│   ├── database.py                 ← MySQL चे सर्व प्रश्न (बातम्या / साप्ताहिक अंक / व्हिडिओ)
│   ├── schema.sql                  ← MySQL टेबल्स (articles, weekly_editions, videos)
│   ├── init_db.py                  ← डेटाबेस + टेबल्स तयार करतो (जुन्या डेटाबेसमध्ये English कॉलम्सही जोडतो)
│   ├── seed_data.py                ← १८ बातम्या + ६८ साप्ताहिक अंक भरतो (seed/ मधून; फक्त रिकाम्या टेबलमध्ये)
│   ├── migrate_sqlite_to_mysql.py  ← जुना SQLite डेटा MySQL मध्ये कॉपी करतो
│   ├── seed/                       ← नमुना डेटा (articles.json, weekly.json)
│   ├── legacy/portal.db            ← जुना SQLite डेटाबेस (फक्त migration साठी)
│   ├── requirements.txt
│   ├── .env.example                ← सेटिंग्जचा नमुना (Git मध्ये)
│   └── .env                        ← तुमच्या खऱ्या सेटिंग्ज / पासवर्ड (Git मध्ये जात नाही)
└── README.md
```

> बॅकएंड बंद असला किंवा पोहोचत नसला तरी साईट चालते — ती आतल्या (`frontend/js/app.js`) डेटावरून दिसते. बॅकएंड चालू असेल तर Admin Panel मधील बदल (बातम्या, अंक, Lead / Popular / Random निवड) साईटवर लगेच मिसळतात.

## 🌟 वैशिष्ट्ये (Key Features)

### १. हेडर व नेव्हिगेशन (Header & Navigation)
- **Home (होम)**: सर्वात वर **प्रमुख बातमी (Lead Story)** — Admin Panel मध्ये ⭐ ने निवडलेली, निवडलेली नसेल तर पहिली राजकीय बातमी; त्याखाली **ताज्या बातम्या (News)** विभाग (सर्व / सामाजिक / राजकीय फिल्टरसह). साप्ताहिक अंक व त्यांचे PDF **Weekly Edition** विभागात.
- **Weekly Edition (साप्ताहिक आवृत्ती)**: स्वतंत्र विभाग — सर्वात नवीन अंकाचे मोठे कार्ड + त्याखाली सर्व अंकांची यादी (**नवीन तारीख वर, जुनी खाली**). प्रत्येक अंकाचे **मुखपृष्ठ = त्या PDF चे पहिले पान**, **शीर्षक = त्या पानावरची मुख्य बातमीची हेडलाईन**, **छोटा मजकूर = त्या बातमीची सुरुवात**, आणि PDF (ऑनलाईन वाचा / डाउनलोड — `WEEKLY_PDF = true`; "३अ" पहा). शोध-पेटीच्या खाली **वर्षाची बटणे** (सर्व / २०२६ / २०२५ …) — वर्ष निवडले की त्या वर्षाचे सर्व अंक दिसतात (शोधही त्या वर्षातच चालतो). यादीत आधी **ताजे १० अंक** दिसतात; त्याखालील **"अधिक वाचा"** बटण दाबले की उरलेले सर्व अंक दिसतात (अंक उघडून Back केल्यावर यादी तशीच उघडी राहते; पान पुन्हा लोड केल्यास पुन्हा १०). शोध: तारीख, महिना किंवा हेडलाईन / मजकुरातला शब्द ("ऑगस्ट २०२६", "पर्यटन") — शोध सर्व अंकांमध्ये चालतो, फक्त १० मध्ये नाही. सध्या **६८ अंक** आहेत (०१ जानेवारी २०२५ ते २६ ऑगस्ट २०२६, दर बुधवारचे); अंकावर क्रमांक दाखवला जात नाही — फक्त तारीख (PDF वर छापलेला अंक क्रमांक दर वर्षी पुन्हा १ पासून सुरू होतो, म्हणून). अंक नसल्यास "सध्या एकही अंक उपलब्ध नाही" कार्ड दिसते.
- **News (बातम्या)**: खालील २ उपविभागांसह ड्रॉपडाऊन मेनू:
  - **Samajik (सामाजिक)**: ग्रामीण व नागरी समाजकारण, महिला सक्षमीकरण, पाणीपुरवठा व विकासकामे.
  - **Rajkiy (राजकीय)**: विधानसभेच्या घडामोडी, पक्षीय विश्लेषण, मंत्रिमंडळ निर्णय व निवडणुका.
- **Blogs (ब्लॉग्स)**: सुप्रसिद्ध स्तंभलेखक आणि विचारवंतांचे वैचारिक लेख.

### २. डिझाइन आणि अलाईनमेंट (Design & Alignment Reference: Xapify)
- **Xapify Templateify स्टँडर्ड**:
  - कंटेनर अलाईनमेंट (1200px ग्रिड व मोबाईल रिस्पॉन्सिव्ह)
  - लोगोवर **Shimmer Shine** अ‍ॅनिमेशन
  - **टॉपबार (Top Bar)**: थेट दिनांक, मराठी वार, तापमान व सोशल मीडिया लिंक्स
  - **ब्रेकिंग न्यूज टिकर (Breaking News Ticker)**: लाल पल्सर बॅज व ऑटो-रोटेटिंग मथळे
  - **हिरो सेक्शन (Hero Featured Grid)**: मोठ्या कव्हर कार्डसह बाजूला २ हायलाईट कार्ड्स
  - **डार्क / लाईट मोड (Dark & Light Mode)**: एका क्लिकवर स्मूथ थीम स्विच (लोकल स्टोरेजमध्ये सेव्ह राहते)
  - **सर्च बार (Search Overlay)**: सर्व बातम्यांमध्ये झटपट शोध घेण्याची सुविधा

### ३. परस्परसंवादी कार्यक्षमता (Interactive Features)
- **Article Reader Modal**: कोणत्याही बातमीवर क्लिक केल्यावर पूर्ण बातमी, ऑडिओ वाचक (Text-To-Speech Marathi), फॉन्ट लहान/मोठा करण्याची सुविधा, प्रिंट आणि WhatsApp शेअर.
- **PDF ई-पेपर रीडर** (`WEEKLY_PDF = true` असताना; सध्या चालू): अंकाचा खरा PDF थेट साईटवरच पान-दर-पान वाचता येतो (pdf.js; ती लायब्ररी फक्त PDF उघडला तेव्हाच डाउनलोड होते). "पान १ / २" निर्देशक, डाउनलोड व नवीन टॅब बटणे; PDF उपलब्ध नसल्यास किंवा लोड न झाल्यास स्पष्ट संदेश + पर्यायी लिंक्स.
- **दैनिक कौल (Daily Poll Widget)**: वाचकांसाठी थेट मत नोंदणी व निकाल.
- **सर्वाधिक वाचलेल्या बातम्या (Popular Posts Widget)**: क्रमांक १ ते ५ रँकिंगसह.
- **फोटोवर कधीही मजकूर नाही:** मोठ्या कार्ड्समध्ये (Popular, Latest Reviews, Videos, मेनूमधील "लोकप्रिय", Home ची पहिली बातमी) फोटो वर आणि त्याच्या **खाली** विभागाचे नाव, शीर्षक, तारीख; PDF / "नवीनतम अंक" / व्हिडिओची लांबी यासारखी लेबल्सही फोटोवर नसतात. नवीन कार्ड करताना `largeCardHTML()` (`frontend/js/app.js`) वापरा — फोटोवर मजकूर लिहू नका.

### ३क. भाषा — मराठी / English

- हेडरमध्ये **मराठी | EN** बटण आहे (फोनवर एकच बटण — तुम्ही ज्या भाषेत जाऊ शकता ती; उघडणाऱ्या मेनूमध्ये पूर्ण बटण). निवडलेली भाषा लक्षात राहते (`localStorage`: `lokmangal-lang`); पत्त्याला `?lang=en` जोडूनही उघडता येते.
- **एका वेळी एकच भाषा:** मराठी निवडली तर सगळे मराठी (मेनू, विजेट्स, बटणे, तारखा, आकडे), English निवडली तर सगळे English (तारीख "26 August 2026", आकडे 0-9). "सर्व बातम्या (All)" सारखे दोन भाषांचे मिश्रण कुठेही येत नाही.
- हे `frontend/js/i18n.js` करते: त्यात इंटरफेसमधील प्रत्येक छोट्या वाक्याचा **मराठी ↔ English शब्दकोश** आहे (`ENTRIES`, आकडे असलेल्यांसाठी `PATTERNS`). नवीन वाक्य जोडले तर त्या यादीत एक ओळ जोडा — नाहीतर ते English मध्येही मराठीच दिसेल.
- **बातम्या / अंकांचा मजकूर:** Admin Panel मधील **English टॅब** (बातमी व अंकाचा फॉर्म) मध्ये English शीर्षक / सारांश / मजकूर / बातमीदार भरा. English निवडल्यावर साईट तोच दाखवते; English भरलेले नसेल तर त्या बातमीचा मराठी मजकूर दिसतो. शोध (search) दोन्ही भाषांत चालतो.
- **आधीपासूनचा मजकूर (१८ बातम्या, ६८ साप्ताहिक अंक) English मध्येही दिसतो:** त्यांचा English मजकूर `frontend/js/content-en.js` मध्ये आहे (आणि `backend/seed/*.json` मध्ये `title_en` … म्हणून) — त्यामुळे Vercel सारख्या बॅकएंडशिवाय चालणाऱ्या होस्टवरही EN दाबताच सगळे English होते. Admin मध्ये त्या बातमीचा English टॅब भरला तर तो (डेटाबेसमधला) मजकूर या फाईलपेक्षा वरचढ ठरतो; फाईल फक्त **रिकामी** जागा भरते.
- **जुन्या डेटाबेससाठी एकदाच:** English मजकूर साठवायला MySQL मध्ये ६ नवे कॉलम्स लागतात. `backend` फोल्डरमध्ये `python init_db.py` चालवा (काहीही हटवत / बदलत नाही: कॉलम्स जोडते आणि आधीच्या १८ बातम्या / ६८ अंकांचा English मजकूर त्यांच्या रिकाम्या English जागी भरते — म्हणजे Admin मध्ये त्यांचा English टॅबही भरलेला दिसतो; तुम्ही स्वतः टाकलेला English कधीच बदलला जात नाही). तोपर्यंत Admin मध्ये English टॅबवर तशी सूचना दिसते आणि English जतन होत नाही (मराठी नेहमी जतन होते). नवीन डेटाबेसमध्ये हे आपोआप असतात.
- साईटच्या कोडमधील ४ रिव्ह्यू, ४ व्हिडिओ व नमुना प्रतिक्रियांचे English आधीच दिले आहे; ते Admin मधून बदलता येत नाहीत (कोडमध्येच आहेत).

### ३अ. पत्ते (URLs), Back बटण व साप्ताहिक PDF
प्रत्येक पानाचा स्वतःचा पत्ता आहे, त्यामुळे ब्राउझरचे **Back / Forward**, रिफ्रेश आणि शेअर केलेल्या लिंक्स नेमक्या त्याच पानावर नेतात:

| पत्ता | कोणते पान |
|---|---|
| (काहीही नाही) | Home — प्रमुख बातमी + बातम्या |
| `#weekly` | Weekly Edition — सर्व अंक (अंक नसताना "सध्या एकही अंक उपलब्ध नाही" कार्ड) |
| `#issue-30` | एका अंकाचे पान (PDF कार्ड, मागील / पुढील अंक). संख्या ही तारखेनुसार क्रम आहे: `#issue-1` = सर्वात जुना (०१ जानेवारी २०२५), सर्वात मोठी = सर्वात नवा |
| `#cat-rajkiy` · `#cat-samajik` · `#cat-blogs` · `#cat-review` | विभाग |
| `#post-12` | एक बातमी / ब्लॉग / रिव्ह्यू |

- Back बटण: लेखावरून Back केल्यास तुम्ही ज्या यादीतून आलात तिथेच, **त्याच स्क्रोल जागी** परत येता.
- ब्रेडक्रंब (Home › साप्ताहिक आवृत्ती › २४ सप्टेंबर २०२५) चा प्रत्येक भाग क्लिक करता येतो; पानाच्या शेवटी "…विभागाकडे परत" व "होम" बटणे आहेत.
- जुनी `#post-3` सारखी लिंक आपोआप `#issue-N` मध्ये बदलते; चुकीचा पत्ता (अंक नसलेला `#issue-N` सुद्धा) Home ला जातो.

**अंकांचा डेटा व फाईल्स** (६८ अंक — तुमच्या `lokmangal saptahik karyakram` फोल्डरमधल्या PDF वरून):

| काय | कुठे |
|---|---|
| PDF | `frontend/assets/pdf/lokmangal-weekly-<क्रमांक>.pdf` (मूळ फाईलची हुबेहूब प्रत; क्रमांक १ = ०१ जानेवारी २०२५ … ६८ = २६ ऑगस्ट २०२६) |
| मुखपृष्ठ (PDF चे पहिले पान) | `frontend/assets/weekly/<क्रमांक>.jpg` (८०० px) व यादीसाठी लहान `<क्रमांक>-s.jpg` (३६० px) |
| तारीख + शीर्षक + छोटा मजकूर | `frontend/js/weekly-data.js` (साईटचा स्वतःचा डेटा — Vercel वरही चालतो) व `backend/seed/weekly.json` (MySQL साठी, `python seed_data.py`) |

- शीर्षक / मजकूर PDF च्या पहिल्या पानावरून वाचला आहे (PDF मध्ये जुना मराठी फॉन्ट असल्याने त्यातला मजकूर कॉपी करता येत नाही); चूक आढळल्यास `weekly-data.js` मध्ये आणि Admin Panel मध्ये सुधारा.
- PDF वर छापलेला **अंक क्रमांक** दर वर्षी पुन्हा १ पासून सुरू होतो (उदा. वर्ष १५ चा अंक १ ते ५२, वर्ष १६ चा ३ ते ३०), म्हणून साईटवर क्रमांक न दाखवता **तारीख** दाखवली आहे. साईटमधला क्रमांक फक्त तारखेचा क्रम आहे.
- `frontend/js/config.js` मध्ये `WEEKLY_PDF = true` — PDF बटणे (ऑनलाईन वाचा / डाउनलोड) दिसतात. **पूर्णपणे बंद करायचे असतील तर** `var WEEKLY_PDF = false;` करा.
- **नवीन अंक जोडणे:** Admin Panel → साप्ताहिक ई-पेपर → नवीन अंक (पुढचा क्रमांक आपोआप सुचवला जातो) → **PDF निवडा**: तारीख फाईलच्या नावावरून (उदा. `Lokmangal Saptahik 02 September 2026.pdf` → "०२ सप्टेंबर २०२६") आणि **मुखपृष्ठ PDF च्या पहिल्या पानावरून** आपोआप भरले जाते (त्याचा लहान preview फॉर्ममध्ये दिसतो; हवे तर तारीख बदला किंवा "फोटो निवडा" ने दुसरे मुखपृष्ठ द्या — हाताने निवडलेले मुखपृष्ठ पुन्हा बदलले जात नाही). तुम्ही फक्त **शीर्षक** (पहिल्या पानावरची मुख्य हेडलाईन) आणि **छोटा परिचय** (बातमीची सुरुवात, २–३ वाक्ये) लिहा, मग "अंक जतन व प्रकाशित करा". PDF आपोआप `assets/pdf/lokmangal-weekly-<क्रमांक>.pdf` म्हणून जतन होतो. अंक यादीत तारखेप्रमाणे जागा घेतो — सर्वात नवीन तारीख वर, "नवीनतम अंक" म्हणून. (मुखपृष्ठ तयार करायला pdf.js इंटरनेटवरून येते; इंटरनेट नसेल तर "फोटो निवडा" ने मुखपृष्ठ द्या.)
- **टीप:** Admin Panel चा डेटा (MySQL) फक्त बॅकएंड चालू असतानाच (`localhost:5000`) साईटवर मिसळतो. Vercel सारख्या होस्टवर बॅकएंडशिवाय साईट आतल्या `weekly-data.js` वरून चालते — तिथे Admin मधून जोडलेले नवे अंक दिसत नाहीत. (नवा अंक Vercel वर हवा असेल तर `weekly-data.js` मध्ये एक ओळ जोडा, PDF व मुखपृष्ठ `assets/` मध्ये ठेवा आणि push करा.)
- फाईल्स दुसरीकडे ठेवायच्या असतील तर खाली "३ब" पहा.

### ३ब. मोठे PDF (१०–३० MB) — साठवण व वाचन

**रीडर कसा वागतो (१०.७ MB / १२ पानांच्या चाचणी-अंकावर मोजलेले):**
- फक्त लागणारा भाग उतरतो (HTTP Range): पान १ साठी सुमारे **१ MB**; पूर्ण १०.७ MB फाईल पार्श्वभूमीत उतरत नाही. वाचकाच्या जवळची पुढची २ पाने आधीच काढली जातात (एकूण ~२.७ MB), त्यानंतर डाउनलोड थांबतो.
- पहिले पान: Slow 4G (१.६ Mbps) वर ~८ सेकंद, चांगल्या 4G (९ Mbps) वर ~२.४ सेकंद. (जुनी पद्धत: पार्श्वभूमीत ~७ MB अनावश्यक उतरत होते.)
- लोड होताना **प्रोग्रेस बार** ("३.१ MB / १०.७ MB"); न दिसलेली पाने शिमर + "पान ३" असे दिसतात; रीडर बंद केल्यावर डाउनलोड लगेच थांबतो.
- **झूम** १००% → १५०% → २००% → ३००% (`+` / `−` बटणे किंवा कीबोर्डवर `+` `-` `0`): पान नव्याने **स्पष्ट** काढले जाते (ताणले जात नाही), वाचन-जागा तशीच राहते, बाजूला सरकवता येते.
- ३६ पानांचा १७ MB अंकही चालतो: दूरची पाने मेमरीतून काढली जातात (एकावेळी ३–४ पाने), त्यामुळे जुन्या फोनवर अडकत नाही.
- डाउनलोड बटणावर फाईलचा आकार ("PDF डाउनलोड • १०.७ MB") दिसतो; फाईल अजून ठेवली नसेल तर बटणांऐवजी "PDF लवकरच उपलब्ध होईल".
- चूक झाल्यास स्पष्ट संदेश: फाईल नाही / PDF नाही / इंटरनेट नाही → "पुन्हा प्रयत्न करा" + "नवीन टॅबमध्ये उघडा" + "डाउनलोड".

**फाईल्स कुठे ठेवायच्या:** `frontend/js/app.js` च्या सुरुवातीला `PDF_BASE` आहे. तेच एक सेटिंग.

| पर्याय | कधी | लक्षात ठेवा |
|---|---|---|
| `assets/pdf/` (साईटच्या आत, सध्याचे) | सध्याचे ६८ अंक (प्रत्येकी सुमारे २ MB, एकूण ≈ **१३३ MB**) | मोठे (१०–३० MB) PDF वापरायचे असतील तर ४२ अंक × १० MB ≈ **४२० MB** होतात. GitHub repo शक्यतो १ GB खाली ठेवायला सांगते (५ GB खाली "strongly"); एक फाईल १०० MB पेक्षा मोठी चालत नाही; आणि PDF बदलली की जुनी आवृत्ती Git इतिहासात **कायम** राहते, म्हणजे repo फुगत जातो. Vercel Hobby चे CLI-अपलोड मर्यादा १०० MB आहे. |
| **स्टोरेज बकेट (शिफारस)** — Cloudflare R2 / Vercel Blob / Amazon S3 | रोजचा वापर, सर्व अंक (वर्षाला ५२ अंक वाढतात) | साईट हलकी राहते, PDF बदलणे म्हणजे फक्त फाईल अपलोड (साईट पुन्हा deploy नको). R2 मध्ये १० GB स्टोरेज मोफत व डेटा-ट्रान्सफर (egress) मोफत आहे (दर कधीही बदलू शकतात — Cloudflare ची किंमत-पाने तपासा). |

बकेट वापरताना: (१) फाईल्स त्याच नावांनी (`lokmangal-weekly-30.pdf` …) अपलोड करा, (२) बकेटला स्वतःचा पत्ता द्या (R2 चा `r2.dev` पत्ता फक्त चाचणीसाठी; प्रत्यक्षासाठी स्वतःचे डोमेन, उदा. `pdf.lokmangal.com`), (३) खालील **CORS** लावा, (४) `frontend/js/app.js` मध्ये बदला:
```js
const PDF_BASE = "https://pdf.lokmangal.com/weekly/";   // शेवटी "/" असू द्या
```
CORS (R2: Bucket → Settings → CORS policy):
```json
[
  {
    "AllowedOrigins": ["https://तुमची-साईट.vercel.app", "https://तुमचे-डोमेन.com"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["Range", "Content-Type"],
    "ExposeHeaders": ["Content-Length", "Content-Range", "Accept-Ranges", "ETag"],
    "MaxAgeSeconds": 86400
  }
]
```
- `ExposeHeaders` **गरजेचे**: ते नसेल तर रीडर चालतो, पण "Range" दिसत नसल्याने पूर्ण फाईल (१०.७ MB) आधी उतरवतो. (चाचणीत मोजले.)
- CORS अजिबात नसेल तर रीडर "PDF येथे दाखवता आला नाही" + "नवीन टॅबमध्ये उघडा / डाउनलोड" दाखवतो; लिंक्स नवीन टॅबमध्ये उघडतात (साईट सुटत नाही).
- बकेट/होस्ट Range चालवतो का तपासा: `curl -I -H "Range: bytes=0-99" <PDF चा पत्ता>` → उत्तर `206 Partial Content` व `Accept-Ranges: bytes` हवे. (Vercel स्वतः हे बरोबर करते — तपासले.) Range नसेल तर पूर्ण फाईल उतरल्यावरच पान १ दिसते.
- PDF वर password/encryption नको; PDF वर `Content-Encoding` (gzip) लावू नका.

**PDF तयार करताना:** फोटो १५०–२०० dpi ला कमी करा, "Optimize for web / Fast Web View" सह एक्स्पोर्ट करा; एक अंक शक्यतो २० MB खाली. अशा PDF चे पहिले पान सर्वात लवकर दिसते.

### ४. मोबाईल अनुभव (Mobile-first)
फोनवर (२८०px ते ६००px), टॅब्लेटवर (६०१–९८०px) आणि लँडस्केपमध्ये साइट वेगळ्या, अ‍ॅपसारख्या लेआउटमध्ये दिसते. सर्व नियम `frontend/css/responsive.css` मध्ये आहेत.
- **कॅटेगरी चिप्स**: हेडर मेनू लपतो; त्याजागी बोटाने स्वाइप करता येणारी चिप्स पट्टी (होम / साप्ताहिक आवृत्ती / सामाजिक / राजकीय / ब्लॉग्स / रिव्ह्यू). निवडलेली चिप आपोआप मध्यात येते.
- **स्लाइड-आऊट मेनू (☰)**: Home, Weekly Edition, News ▾ (Samajik, Rajkiy), Blogs, Reviews + शोध + Popular Items. डावीकडे स्वाइप करून किंवा बाहेर टॅप करून बंद होतो.
- **फोटो-प्रथम मुख्य बातमी**: पूर्ण रुंदीचा फोटो, मोठे मथळे, एका बोटाने पोहोचता येणारी ४४px+ बटणे; कार्ड्स स्क्रीनच्या कडेपर्यंत.
- **बॉटम-शीट पॉपअप**: ई-पेपर व व्हिडिओ खालून वर येणाऱ्या शीटमध्ये उघडतात; शीर्षक पट्टी खाली ओढून बंद करता येते.
- **Back बटण / Back-स्वाइप**: मेनू किंवा शीट उघडी असताना Back दाबल्यास ती बंद होते, साइट सुटत नाही.
- **लेख पान**: संबंधित बातम्या स्वाइप पट्टीत, शेअर बटणे २×२ ग्रिडमध्ये, कमेंट फॉर्म १६px (iPhone वर झूम होत नाही).
- **Follow Us**: फोन/टॅब्लेटवर *Labels* च्या ठीक खाली येते — ब्रँड-रंगाची आयकॉन कार्ड्स (Facebook, X, YouTube, WhatsApp) व "फॉलो करा / सबस्क्राईब / जॉईन करा" ओळ. डेस्कटॉपवर ते पूर्वीसारखे उजव्या कॉलममध्येच राहते. (हे `frontend/js/app.js` मधील `initFollowPlacement()` करते; ब्रँड रंग `frontend/css/responsive.css` मधील "E2. FOLLOW US WIDGET" विभागात.)
- **नॉच / सेफ-एरिया, डार्क मोड** (ब्राउझर बारचा रंगही बदलतो), `prefers-reduced-motion` ला आदर.

## 🚀 सुरू कसे करावे (How to Run Locally)

### १. बॅकएंड (Python + MySQL)

पूर्वतयारी: **Python 3.10+** आणि **MySQL 8** (MySQL service सुरू असावी).

```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate               # Mac / Linux:  source .venv/bin/activate
pip install -r requirements.txt

copy .env.example .env               # Mac / Linux:  cp .env.example .env
#   .env उघडून DB_USER / DB_PASSWORD तुमच्या MySQL प्रमाणे भरा

python init_db.py --seed             # डेटाबेस + टेबल्स तयार करतो व १८ बातम्या + ६८ साप्ताहिक अंक भरतो
python app.py
```

| काय | पत्ता |
|---|---|
| वेबसाईट | http://localhost:5000/ |
| Admin Panel | http://localhost:5000/admin/ |
| बॅकएंड तपासणी | http://localhost:5000/api/health |

- `init_db.py` कितीही वेळा चालवला तरी चालतो — काहीही पुसले जात नाही. `--seed` फक्त **रिकाम्या** टेबल्समध्ये नमुना डेटा भरतो (तेच id / अंक पुन्हा लिहायचे असतील तर `python seed_data.py --force`).
- **जुना SQLite डेटा (`data/portal.db`) हवा असेल:** `--seed` ऐवजी `python init_db.py` नंतर `python migrate_sqlite_to_mysql.py` चालवा. बातम्या, अंक, तारखा आणि Lead / Popular / Random निवड जशीच्या तशी कॉपी होते (फाईल `backend/legacy/portal.db`; दुसरी फाईल हवी तर `--sqlite <फाईल>`). लक्षात ठेवा: त्या जुन्या फाईलमध्ये ते ४२ नमुना साप्ताहिक अंकही आहेत — migration चालवल्यास ते परत येतात (Admin Panel मधून हटवता येतात).
- **फोनवर तपासायचे असेल:** फोन व PC एकाच वाय-फायवर ठेवून `http://<PC चा IP>:5000/` उघडा (`.env` मध्ये `HOST=0.0.0.0` असताना; Windows Firewall विचारले तर "Private network" ला परवानगी द्या).
- MySQL चालू नसेल तर `python app.py` सुरू होतो पण "WARNING: cannot use MySQL yet" दाखवतो; API `503` देते आणि साईट आतल्या डेटावरून चालते.
- PowerShell मध्ये `.venv\Scripts\activate` ला "running scripts is disabled" आले तर activate न करता थेट `.venv\Scripts\python init_db.py --seed` आणि `.venv\Scripts\python app.py` चालवा (किंवा CMD वापरा).
- पोर्ट आधीच दुसऱ्या प्रोग्रामने घेतला असेल तर `python app.py` स्पष्ट संदेश देऊन थांबतो; `.env` मध्ये दुसरा `PORT` ठेवा (आणि फ्रंटएंड वेगळ्या सर्व्हरवरून चालवत असाल तर `frontend/js/config.js` मधील `DEV_API_PORT` तोच ठेवा).

```bash
cd frontend
python -m http.server 3000           # किंवा:  npx serve -l 3000
```

`http://localhost:3000/` उघडा. साईट आतल्या डेटावरून चालते. बॅकएंड `localhost:5000` वर चालू असेल तर साईट तो आपोआप शोधून त्याचा डेटा मिसळते. (Admin Panel ला बॅकएंड लागतोच.)

### ४. API (`/api/...`)

| Method | पत्ता | काम |
|---|---|---|
| GET | `/api/articles` (`?category=` `?search=` `?placement=lead\|popular\|random` `?limit=`) | बातम्या |
| GET | `/api/articles/<id>` | एक बातमी |
| POST | `/api/articles` | नवी बातमी (`title` गरजेचे) |
| PUT / POST | `/api/articles/<id>` | बातमी बदला |
| POST | `/api/articles/<id>/toggle-placement` | `{"field": "is_lead\|is_popular\|is_random", "value": 1}` (Lead एकावेळी एकच) |
| DELETE | `/api/articles/<id>` | हटवा |
| GET | `/api/weekly` (`?limit=`) | साप्ताहिक अंक |
| POST | `/api/weekly` | अंक जोडा / बदला (`issue_no`, `title` गरजेचे) |
| DELETE | `/api/weekly/<अंक क्रमांक>` | अंक हटवा |
| GET | `/api/videos` (`?limit=`) | अपलोड केलेले व्हिडिओ (सर्वात नवीन वर) |
| GET | `/api/videos/<id>` | एक व्हिडिओ |
| POST | `/api/videos` | व्हिडिओ जोडा: `title` व `video_url` (आधी `/api/upload/video` ने मिळालेला `assets/videos/...`, किंवा YouTube / थेट व्हिडिओ फाईलची `https://` लिंक) गरजेचे; `title_en`, `description`, `description_en`, `thumbnail`, `duration_sec`, `size_bytes` ऐच्छिक |
| PUT / POST | `/api/videos/<id>` | व्हिडिओ बदला (नवा `video_url` दिला तर जुनी फाईल डिस्कवरून जाते) |
| DELETE | `/api/videos/<id>` | हटवा — व्हिडिओ फाईल व तिचा `video-poster_...` फोटोही डिलीट होतो (दुसरा व्हिडिओ वापरत असेल तर नाही) |
| POST | `/api/upload/image` · `/api/upload/pdf` · `/api/upload/video` | फोटो / PDF / व्हिडिओ अपलोड (form-data `file`; PDF सोबत `issue_no`). व्हिडिओ: mp4, m4v, mov, webm, ogv — फाईलचे पहिले बाइट्स तपासले जातात (नाव बदललेली text फाईल नाकारली जाते) |
| DELETE | `/api/upload/video` | `{"url": "assets/videos/..."}` — अपलोड झालेली पण कोणत्याही व्हिडिओला न जोडलेली फाईल परत घेतो |
| GET | `/api/stats` · `/api/media` · `/api/health` | डॅशबोर्ड आकडे · अपलोड केलेल्या फाईल्स · तपासणी |

- उत्तर नेहमी JSON: `{"success": true, ...}` किंवा `{"success": false, "error": "..."}`. MySQL बंद असेल तर `503`.
- PDF अपलोड आधी `.part` फाईलमध्ये उतरतो, `%PDF-` तपासला जातो, मगच जुन्या फाईलची जागा घेतो — अर्धवट अपलोडमुळे चांगला अंक खराब होत नाही.
- **Admin Panel मधून जोडलेल्या बातम्यांचे id १०,००० पासून सुरू होतात** (`schema.sql` मुळे, नव्या डेटाबेसमध्ये आपोआप). साईट बॅकएंडचा डेटा आपल्या आतल्या यादीत id नुसार मिसळते, आणि त्या यादीत आधीच बातम्यांचे id १–२२ व साप्ताहिक अंकांचे १००१–१०४२ आहेत; नवा id त्यांना कधी टकरावू नये म्हणून ही सुरुवात. **डेटाबेस आधीच तयार झालेला असेल तर** MySQL मध्ये एकदाच चालवा: `ALTER TABLE articles AUTO_INCREMENT = 10000;` (आतल्या डेटातील ४ रिव्ह्यू — id १९ ते २२ — डेटाबेसमध्ये नाहीत, म्हणून Admin Panel मध्ये दिसत नाहीत.)

### ६. Admin Panel (`/admin/`)

**Admin ची भाषा:** डावीकडील मेनूमध्ये (वर) **मराठी | English** बटणे आहेत — निवडलेली भाषा **एकावेळी एकच** दिसते (मेनू, शीर्षके, बटणे, याद्यांची शीर्षके, सूचना, पुष्टी-संवाद). निवड लक्षात राहते (`localStorage`: `lokmangal-admin-lang`). हे `frontend/admin/admin-i18n.js` करते (शब्दकोश; नवीन वाक्य जोडायचे तर तिथे एक ओळ जोडा). बातम्या / अंकांचा मजकूर हा **डेटा** आहे — तो भाषा बदलल्याने बदलत नाही (त्याचे Marathi | English टॅब वेगळे). "नवीन बातमी" फॉर्ममध्ये खालच्या छोट्या सूचना (subtext) ठेवलेल्या नाहीत; "पोर्टलवरील स्थान" (Lead / Popular / Random) चे तीन चौकोन लहान आहेत.

**बातमीचा सविस्तर मजकूर = साधा text:** तिथे HTML tags (`<p>`, `<strong>` …) लिहावे लागत नाहीत व दिसतही नाहीत. साधे लिहा; **एक ओळ रिकामी सोडली की नवा परिच्छेद** होतो (वेबसाईटला `<p>` परिच्छेद जातात; `&`, `<`, `>` जसे लिहिले तसे दिसतात). जुनी बातमी संपादनासाठी उघडली तरी tags दिसत नाहीत; मजकूर **न बदलता** जतन केला तर तिचे जुने formatting (उदा. ठळक "सोलापूर:") तसेच राहते, मजकूर बदलला तर तो साध्या परिच्छेदांत जतन होतो. (कोणी HTML tags सह मजकूर paste केला तर तो जसाच्या तसा जतन होतो.) English टॅबचा मजकूरही असाच.

| टॅब | काय करता येते |
|---|---|
| डॅशबोर्ड | एकूण बातम्या / अंक, सध्याची Lead Story, अलीकडील नोंदी |
| बातम्या व्यवस्थापन | नवी बातमी (फोटो अपलोडसह) — **मराठी | English टॅब**: एकदा मराठीत, एकदा English मध्ये भरा (शीर्षक, सारांश, मजकूर, बातमीदार), बदल, हटवा, शोध व फिल्टर. प्रत्येक बातमीचे स्थान निवडता येते: ⭐ **Lead Story** (Home वर सर्वात वर — एकावेळी एकच), 🔥 **Popular Posts** (डावी बाजू), 🎲 **Random Posts** (उजवी बाजू) |
| साप्ताहिक ई-पेपर | नवा अंक (शीर्षक व परिचय **मराठी + English टॅबवर**): **PDF निवडा** → तारीख व मुखपृष्ठ आपोआप भरतात (डिफॉल्ट मर्यादा ५० MB), तुम्ही शीर्षक + छोटा परिचय लिहिता. **✏️ संपादन बटण:** आधीच्या अंकाचे शीर्षक / तारीख / परिचय / मुखपृष्ठ / PDF बदलता येते (अंक क्रमांक बदलता येत नाही). नवा अंक आधीच असलेल्या क्रमांकाने जतन करताना "जुना बदलायचा का?" असे विचारले जाते. हटवा: अंक वेबसाईटवरूनही जातो; त्याची PDF / फोटो फाईल फोल्डरमध्ये राहते |
| व्हिडिओ अपलोड | **नवीन व्हिडिओ अपलोड करा** → **व्हिडिओ फाईल निवडा** (किंवा ड्रॅग करा; MP4 / WebM उत्तम, डिफॉल्ट कमाल २०० MB) **किंवा YouTube / थेट .mp4 ची लिंक paste करा** (लिंक दिली तर काहीच अपलोड होत नाही; वेबसाईटवर YouTube त्याच्या स्वतःच्या प्लेअरमध्ये तिथेच चालतो, त्याचा thumbnail आपोआप येतो) + **शीर्षक** (मराठी + English टॅब) + ऐच्छिक वर्णन → जतन. फाईल निवडताच ब्राउझर व्हिडिओची **लांबी** वाचतो आणि त्यातून **एक फोटो** (वेबसाईटच्या कार्डचा thumbnail) घेतो; फाईल **जतन करतानाच** (प्रोग्रेस बारसह) अपलोड होते, म्हणून "रद्द करा" केले तर काहीच मागे राहत नाही. **✏️ संपादन:** शीर्षक / वर्णन बदला किंवा नवी फाईल निवडा (जुनी फाईल डिस्कवरून जाते). **हटवा:** व्हिडिओ वेबसाईटवरूनही जातो आणि फाईल कायमची डिलीट होते |

- **सर्वात वर कोण? (सर्वात अलीकडे बदललेली बातमी):** Admin मध्ये बातमी **जतन (Save) केली**, दुसऱ्या विभागात हलवली (राजकीय → सामाजिक / रिव्ह्यू वगैरे) किंवा ⭐ Lead / 🔥 Popular / 🎲 Random **चालू** केले — की ती बातमी वेबसाईटवर (refresh नंतर) लगेच सर्वात वर येते: Home च्या ताज्या बातम्या, Popular, Random, Latest Reviews आणि त्या विभागाच्या पानावर. (Popular / Random **बंद** केल्याने किंवा दुसरी बातमी Lead झाल्याने जुनी बातमी वर जात नाही.) हे `articles.updated_at` या कॉलमवर चालते; जुन्या डेटाबेसमध्ये `backend` फोल्डरमध्ये एकदा `python init_db.py` चालवा (कॉलम जोडते, काहीही हटवत / बदलत नाही; आधीच्या सर्व बातम्यांना एकच वेळ मिळते, त्यामुळे क्रम बदलत नाही). बॅकएंडशिवायच्या होस्टवर (Vercel) क्रम कोडमधलाच राहतो.
- प्रत्येक बातमी / अंकाची स्वतःची लिंक असते (`#post-<id>`, `#issue-<क्रमांक>`); ती WhatsApp वर शेअर करता येते, refresh / bookmark केली तरी तीच बातमी उघडते.
- Admin मध्ये बदल (edit) केला तर वेबसाईटवर बदल दिसतो; बातमी / अंक हटवला तर वेबसाईटवरूनही जातो — जुन्या नमुना बातम्या / अंक सुद्धा. फक्त साईटच्या कोडमधील ४ रिव्ह्यू (id १९–२२) Admin मध्ये दिसत नाहीत व हटवता येत नाहीत.
- "सविस्तर बातमी मजकूर" बॉक्समध्ये साधा मजकूर (HTML टॅग शिवाय) लिहिला तर रिकामी ओळ सोडून नवा परिच्छेद सुरू होतो आणि वेबसाईटवर तो वेगळा परिच्छेद दिसतो; `<p>`, `<b>` असे HTML टॅग वापरले तर मजकूर जसा लिहिला तसाच राहतो. फोटो निवडला नाही तर एक डिफॉल्ट फोटो लागतो — प्रत्येक बातमीला स्वतःचा फोटो अपलोड करा.
- सर्व बातम्या, अंक, फोटो-नावे, Lead / Popular / Random निवड MySQL मध्ये साठवल्या जातात; server restart नंतरही टिकतात.
- **Admin Panel फोन / टॅबलेटवरही नीट चालतो** (२८० px पासून): मेनू डावीकडून सरकणारा drawer (बटण / बाहेर टॅप / Esc ने बंद), याद्या कार्ड्ससारख्या, फॉर्म्स पूर्ण-स्क्रीन शीटसारखे (जतन करा बटण नेहमी खाली दिसते), बटणे ४४ px (बोटाने दाबायला सोपी), फॉर्ममधील अक्षरे १६ px (iPhone झूम करत नाही).
- **Admin Panel फक्त बॅकएंड असलेल्या पत्त्यावरच काम करतो** (`http://localhost:5000/admin/` किंवा बॅकएंड ठेवलेला सर्व्हर). Vercel सारख्या फक्त-फ्रंटएंड होस्टवर `/admin/` पान उघडते, पण तिथे Python + MySQL बॅकएंड नसल्याने त्याला काहीच वाचता येत नाही: आकडे "—" दिसतात आणि वर लाल सूचना येते ("या पत्त्यावर बॅकएंड नाही") — अंक / बातम्या हरवलेल्या नसतात, साईटवर ते जसेच्या तसे असतात. कनेक्शन तुटले तरी (बॅकएंड बंद, MySQL बंद, यादी अर्धवट आली) याच जागी स्पष्ट सूचना येते; चुकीचे "०" कधी दाखवले जात नाही.
- तारीख: वेबसाईट "२ सप्टेंबर २०२६", "2 September 2026", "02-09-2026", "2026-09-02" वाचते; दुसऱ्या पद्धतीची तारीख वाचता आली नाही तर तो अंक यादीत सर्वात वर येतो.
- बॅकएंड सुरू असताना वेबसाईट डेटाबेसला **सत्य** मानते: Admin मध्ये शेवटची बातमी / शेवटचा अंक हटवल्यानंतरही साईटच्या आतल्या (built-in) जुन्या नोंदी परत येत नाहीत.
- वाचकांच्या प्रतिक्रिया (comments) **डेटाबेसमध्ये नाहीत** — त्या फक्त त्या वाचकाच्या ब्राउझरमध्ये साठवल्या जातात (इतर वाचकांना दिसत नाहीत). प्रत्येक बातमीखाली दिसणाऱ्या नमुना प्रतिक्रिया `frontend/js/app.js` मध्ये लिहिलेल्या आहेत (खऱ्या नाहीत) — साईट सार्वजनिक करण्यापूर्वी त्या काढा.
- "वाचक संख्या (Views)" हा तुम्ही लिहिलेला मजकूर आहे; तो आपोआप मोजला जात नाही.

**बॅकअप:** बातम्या व अंकांची माहिती आता MySQL मध्ये आहे (Git मध्ये नाही), म्हणून नियमित बॅकअप घ्या: `mysqldump -u root -p lokmangal_news_portal > backup.sql`. फोटो / PDF साठी `frontend/assets/` फोल्डर कॉपी करा (किंवा Git मध्ये commit करा). **व्हिडिओ** Git मध्ये जात नाहीत, म्हणून `frontend/assets/videos/` फोल्डर वेगळा कॉपी करा (व्हिडिओंची नावे / शीर्षके `mysqldump` मध्ये येतात, फाईल्स नाही).

## 🌐 इंटरनेटवर ठेवताना (Deployment)

1. **Vercel (फ्रंटएंड):** Project → Settings → General → **Root Directory = `frontend`**. (हे केले नाही तर साईट 404 देईल — कारण `index.html` आता `frontend/` च्या आत आहे.)
2. **बॅकएंड:** Vercel वर Python + MySQL चालत नाही; VPS / Railway / Render सारखी जागा + MySQL लागते. `python app.py` फक्त विकासासाठी; प्रत्यक्षासाठी:
   ```bash
   pip install waitress
   waitress-serve --listen=0.0.0.0:5000 app:app          # Linux: gunicorn -w 2 -b 0.0.0.0:5000 app:app
   ```
3. दोन्ही जोडा: `frontend/js/config.js` मध्ये `API_BASE_PRODUCTION = "https://api.तुमचे-डोमेन.com"` आणि बॅकएंडच्या `.env` मध्ये `CORS_ORIGINS=https://तुमची-साईट.vercel.app,https://तुमचे-डोमेन.com`.
4. **सुरक्षा — महत्त्वाचे:** Admin Panel व API ला सध्या **लॉगिन नाही**; पत्ता माहित असलेला कोणीही बातम्या बदलू / हटवू शकतो. फक्त स्वतःच्या PC वर वापरताना `.env` मध्ये `HOST=127.0.0.1` ठेवा. इंटरनेटवर ठेवण्यापूर्वी लॉगिन लावा (किंवा Nginx Basic-Auth / VPN), आणि MySQL साठी `root` ऐवजी फक्त या डेटाबेसचे अधिकार असलेला वेगळा user बनवा.
5. अपलोड केलेले फोटो / PDF / **व्हिडिओ** बॅकएंडच्या `IMAGES_DIR` / `PDF_DIR` / `VIDEO_DIR` मध्ये जतन होतात (व्हिडिओ मोठे असल्यामुळे `frontend/assets/videos/` Git मध्ये जात नाही — ते ज्या PC / सर्व्हरवर बॅकएंड चालतो तिथेच राहतात, आणि वेबसाईटवर ते **बॅकएंड चालू असलेल्या पत्त्यावरच** दिसतात; Vercel सारख्या फक्त-फ्रंटएंड होस्टवर नमुना व्हिडिओ दिसतात). फ्रंटएंड वेगळ्या होस्टवर असेल तर ते फोल्डर्स त्या होस्टवरूनही उपलब्ध असले पाहिजेत (PDF साठी वरचे `PDF_BASE` + स्टोरेज बकेट हा उत्तम पर्याय).
